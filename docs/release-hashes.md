# Release Hashes

This file records the canonical SHA-256 hashes of the compiled `lumenflow.wasm`
binary for every release. These hashes are used by `scripts/verify-build.sh` to
confirm that a locally produced binary matches the official release artifact.

## How to verify

```bash
# Install the pinned toolchain
rustup toolchain install           # reads rust-toolchain.toml automatically

# Verify against a specific release tag
./scripts/verify-build.sh v1.0.0

# Or set VERSION in the environment
VERSION=v1.0.0 ./scripts/verify-build.sh
```

The script will:
1. Build the WASM from your local source using `--locked` (ensuring Cargo.lock
   is respected exactly).
2. Compute the SHA-256 of the resulting binary.
3. Compare it against the entry in this table.
4. Exit `0` on match, `1` on mismatch.

### Verifying a downloaded CLI archive

**Linux / macOS:**

```bash
# Download the archive and its checksum, then verify
sha256sum lumenflow-v1.0.0-x86_64-unknown-linux-gnu.tar.gz
# Compare the output against the matching row in the table above.
```

On macOS, `shasum -a 256 <file>` is equivalent if `sha256sum` is unavailable.

**Windows (PowerShell):**

```powershell
Get-FileHash .\lumenflow-v1.0.0-x86_64-pc-windows-msvc.zip -Algorithm SHA256
```

Compare the resulting `Hash` value (case-insensitive) against the
`x86_64-pc-windows-msvc` row for the release version in the table above.

## Ensuring a reproducible build

The following factors are pinned to guarantee byte-for-byte identical output
across machines:

| Factor | How it is pinned |
|--------|-----------------|
| Rust compiler version | `rust-toolchain.toml` — `channel = "1.87.0"` |
| Dependency versions | `Cargo.lock` committed to the repository |
| Compiler flags | `[profile.release]` in root `Cargo.toml` (`codegen-units = 1`, `opt-level = "z"`, `strip = "symbols"`) |
| Build command | `cargo build --target wasm32-unknown-unknown --release --package lumenflow --locked` |

If your locally computed hash differs, verify that:

- You are using the exact toolchain version in `rust-toolchain.toml` (run
  `rustc --version` and compare).
- `Cargo.lock` has not been modified locally (`git diff Cargo.lock`).
- You used the `--locked` flag (prevents Cargo from updating dependencies).

## Verifying SLSA provenance

Every release also publishes a SLSA provenance attestation generated by the
hosted CI build. The attestation is attached to the GitHub Release as a
`.intoto.jsonl` file (for example `lumenflow-v1.0.0.intoto.jsonl`) and covers
all release artifacts: the `lumenflow.wasm` binary, the CLI binaries, and the
SDK npm package.

This provides a **SLSA Level 2** guarantee: the artifacts were built by a
hosted build service (GitHub Actions) and the provenance was signed by that
service, so you can confirm the artifacts were produced from this repository's
source by the official workflow rather than on an untrusted machine.

### 1. Download the attestation

```bash
# Download the provenance file attached to the release
gh release download v1.0.0 --pattern '*.intoto.jsonl'

# Or via the GitHub web UI: Releases -> v1.0.0 -> Assets -> *.intoto.jsonl
```

### 2. Install `slsa-verifier`

```bash
# Install the pinned slsa-verifier release (Linux x86_64 example)
curl -sSL -o slsa-verifier \
  https://github.com/slsa-framework/slsa-verifier/releases/download/v2.6.0/slsa-verifier-linux-amd64
chmod +x slsa-verifier
sudo mv slsa-verifier /usr/local/bin/

# Confirm the installation
slsa-verifier version
```

### 3. Verify an artifact

Run `slsa-verifier verify-artifact` against each downloaded artifact, pointing
it at the provenance file and the repository that produced the build:

```bash
# WASM binary
slsa-verifier verify-artifact lumenflow.wasm \
  --provenance-path lumenflow-v1.0.0.intoto.jsonl \
  --source-uri github.com/<org>/lumenflow \
  --source-tag v1.0.0

# CLI binaries (repeat for each platform artifact)
slsa-verifier verify-artifact lumenflow-cli-linux-amd64 \
  --provenance-path lumenflow-v1.0.0.intoto.jsonl \
  --source-uri github.com/<org>/lumenflow \
  --source-tag v1.0.0

# SDK npm package
slsa-verifier verify-artifact lumenflow-sdk-1.0.0.tgz \
  --provenance-path lumenflow-v1.0.0.intoto.jsonl \
  --source-uri github.com/<org>/lumenflow \
  --source-tag v1.0.0
```

A successful verification prints `PASSED: Verified SLSA provenance` and exits
`0`. Any mismatch (wrong source, wrong tag, tampered artifact) exits non-zero.

> **Note:** `scripts/verify-build.sh` performs this provenance check
> automatically when a `.intoto.jsonl` file is present for the requested
> version, in addition to comparing the locally built WASM hash against the
> table above.
